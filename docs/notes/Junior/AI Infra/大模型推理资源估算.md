# 大模型系统设计题：推理资源估算

**假设要部署视觉语言大模型图像分析服务，考虑采用 GLM-5.3-Flash。请估算 token 消耗，以及使用 H200 本地部署所需的 GPU 数量。**

以下为统一的计算假设：

- 高峰时，113 路图像源同时使用；请求总量按每天运行 8 小时、每月运行 22 天计算，运行期间所有图像源均参与分析。
- 每路图像源每 3 分钟抽取一张 1080p 图像，每张图像形成一次独立请求，不携带历史对话。
- 模型完成画面人数估计和简短场景描述。每次输入包含图像及约 200 个文本 token，最终回答最多 100 个 token；模型生成的思考 token 也需要计入推理开销。
- 从请求进入推理服务到返回完整结果，95% 的请求应在 30 秒内完成。
- 本地部署统一采用 **H200 SXM，单卡显存 141 GB**。推理精度、并行方式和批处理策略由各组确定。
- **GPU 资源仅核算模型推理，包括模型内部的视觉编码；不考虑视频编解码、抽帧和模型外部的图像预处理开销。**

## 1. 建立负载模型

计算平均请求到达率，并比较两种情况：各路图像源错开时间发送请求，以及所有图像源同时发送请求。两种情况的平均请求量相同，所需资源是否相同？为什么？

根据 GLM-5.3-Flash 的图像处理方式，估算每张图像对应的视觉 token 数。

## 2. 估算 token 消耗

计算每天和每月的请求数，以及输入、输出 token 总量。

输入部分需考虑文本和图像的计量方式；输出部分需区分思考 token 与最终回答 token，并说明使用的是平均长度估计还是上限预算。

## 3. 估算单个模型实例的资源需求

查阅 GLM-5.3-Flash 的模型结构，区分总参数量与激活参数量，说明它们分别如何影响显存占用和计算量。

选择推理精度，估算模型权重、推理缓存、模型内部视觉编码及运行时开销，判断一个模型实例至少需要多少张 H200，并说明采用的并行方式及通信开销。

## 4. 估算 GPU 总量

根据实测或有来源的性能数据，估算满足吞吐与延迟要求所需的模型实例数和 H200 总数。说明批处理、排队及容量余量如何影响结果，并分别给出错峰请求和同步突发请求下的配置。
